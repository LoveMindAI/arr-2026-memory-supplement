# Reproducibility materials

Two archives. **software** holds every script and prompt behind a number in the paper. **data** holds the aggregate result files behind every number, the facts file that links each number to its result file, the field-count codes (with page references; a few notes keep short quotations from the public papers), and a fully synthetic public stand-in for the corpus. Nothing here contains participants' words, recordings, questionnaire answers, or any per-person output; the scripts that produce per-person files read the PARSEL corpus, which is available from its owners under their terms.

## How to read it

- `data/paper_notes/FACTS_v2.md` lists every number the paper uses, each with the result file it comes from. It is built by `software/scripts/build_facts.py`.
- The table below groups those facts and names, for each result file, the scripts that mention it (the script that writes it and any that read it).
- A result file with a suffix (`_filled`, `_comply`, `_gaze`, `_voice`, `_tx_v3`) comes from the same script as the file without it, run with the environment switch named in that script (for example `LOC_FILL=1 python3 scripts/memorability.py`).
- `data/twin_public/` is the stand-in: 293 invented people, 583 calls and 1,166 memories, coded by Claude Haiku 5.5 and GPT-6 Luna, with one author's codes for 40 memories in `author_codes/`. Its `README.md`, `SOURCES.md`, `VALIDATION.md` and `LEAK_AUDIT.md` describe how it was built and checked.
- Model calls went through OpenRouter and the providers' APIs with the model names given in the paper's appendix; prompts are in the scripts verbatim (`scripts/prompts.py`, `scripts/judge.py`, `scripts/locate_moments.py`, `codebook/spec_v351_FROZEN.py`, `scripts/NORMS_NOTE_v2_APPROVED.txt`). Paths are written for one machine and need repointing. The aggregates in `data/` are the paper's numbers; regenerating `FACTS_v2.md` itself needs PARSEL and the per-report files we withhold, so a reviewer without that access can check each number against its aggregate file but not rebuild it from raw data. `software/requirements.txt` lists the Python packages; the stand-in run needs only the first group.
- **Running on PARSEL.** Researchers granted access to PARSEL (Hrkalovic et al., 2025) can rerun the model-based analyses: transcribe the calls with `scripts/transcribe_v2.py`, point `scripts/prompts.py` at those transcripts and the release's memory reports and questionnaires, then run annotation (`scripts/code_v35.py`), prediction, judging (`scripts/judge.py`) and the analysis scripts named in the table below, and rebuild the facts file with `scripts/build_facts.py`. **Running the method on the stand-in.** With an OpenRouter key, `bash software/scripts/run_on_standin.sh data/twin_public S01,S02` exports two synthetic sessions into the layout the pipeline reads (`software/twin_public/export_for_pipeline.py`, selected with the `MEMORY_DATA` switch in `scripts/prompts.py`), then predicts each memory with no information and with the person's other memories, runs the three judges, annotates reports and predictions with the frozen codebook, and computes person-specific fit. Two sessions cost about $0.65 in our October 2026 run; `--budget` caps only the prediction step, and outputs are reused by ID, so use one session selection per copy of `software/` (the script refuses to mix them). The stand-in has no audio or video, so the voice, gaze and media analyses do not run on it, and its numbers are not the paper's. In the agreement files (`HUMAN_AGREEMENT.json` and the FACTS agreement rows) an answer's status "trusted" is the paper's "included". Analyses built on the authors' own annotations are reported as aggregates only; the full annotations are available on request to researchers with PARSEL access.

## Coding assistance

Most of the analysis code in `software/` was written by AI coding agents (Claude Code with Claude Opus models, and Codex with GPT models) working under the authors' direction. The authors specified each analysis and its parameters, and every number in the paper is traced from these scripts' outputs through `data/paper_notes/FACTS_v2.md`.
